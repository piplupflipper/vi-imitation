# 起動時間、メモリの使用量、実行ファイルのサイズ（NFR-05）

要件定義の NFR-05 は「起動時間、メモリの使用量、実行ファイルのサイズの目標値は未定で、計測してから定める」としている。
この文書は、端末で動くエディタ（#111 の後）の 3 つの量を 2026-11-16 に測った値と、目標値の案を書く（#120）。
目標値は、2026-11-16 にオーナーが案の B（推奨）を採り（#122）、要件定義の NFR-05 に書いた。
この文書には、決めた根拠になった実測と、比べた案を残す。

## 結論

10,000 行のファイルを開いたとき、起動から最初の画面までは中央値 7.5 ms で、本体の RSS（物理メモリに載っている量）は約 10 MiB だった。
同じ条件の Vim 9.1（`--clean`）は 16.0 ms と 13.5 MiB、Neovim 0.12.5（`--clean`、2 つのプロセスの合計）は 17.4 ms と 22.6 MiB だった。
100,000 行（6.8 MB）のファイルでは、本体の RSS が約 35 MiB になり、Vim（20.1 MiB）と Neovim（29.3 MiB）より大きい。
tree-sitter と LSP の拡張機能を起動した後の本体の RSS は約 14.7 MiB で、拡張機能のプロセス（偽の言語サーバーを含む）は別に約 35 MiB を使う。
本体の実行ファイルは 7,447,701 バイト（7.10 MiB）で、シンボルとデバッグ情報を削ると 4,960,416 バイト（4.73 MiB）になる。

目標値の案は[目標値の案](#目標値の案)に、項目ごとに 3 案と推奨を書く。
オーナーは全ての項目で推奨の B を採った。
起動から最初の画面までが 20 ms、本体の RSS が 16 MiB、本体の実行ファイルが 10 MiB で、どれも拡張機能なしで 10,000 行のテキストファイルを開いた条件である（実行ファイルは `make build` の本体）。

| 項目 | 値 |
|---|---|
| CPU | AMD Ryzen 9 8945HX（32 論理コア） |
| メモリ | 29 GiB |
| OS | Ubuntu 24.04.4 LTS、Linux 7.0.0-31-generic |
| Go | 1.27.4 linux/amd64 |
| Python | 3.14.5（計測の道具を動かす） |
| コミット | `8a367ac`（main） |
| ビルド | `make build MUSL_CC=gcc`（`-trimpath`。シンボルとデバッグ情報は削らない） |
| 比較の Vim | 9.1.0016（Ubuntu の `vim` 2:9.1.0016-1ubuntu7.20 の `vim.basic`） |
| 比較の Neovim | 0.12.5（mise で入れた公式のビルド） |

手元に musl-gcc が無いので、tree-sitter の拡張機能は `MUSL_CC=gcc` でビルドし、glibc を静的にリンクした。
配布物（`make dist`）の tree-sitter の拡張機能は musl を静的にリンクするので、この拡張機能のサイズと RSS は配布物と違う。
本体と、tree-sitter 以外の拡張機能は `CGO_ENABLED=0` でビルドするので、`MUSL_CC` に依存しない。

このマシンは共用で、他のプロセスが同時に動いていた可能性がある。
計測の前後に読んだ `/proc/loadavg` の 1 分間の平均は 0.37〜1.45 だった。
15 分間の平均は、計測を始めた 12:23 に 23.50、終えた 12:41 に 8.00 で、計測の前に重い処理が動いていたことを示す。
この影響を見るため、全ての条件を 20 回ずつ測る組を 3 回（12:23〜12:29、12:29〜12:35、12:35〜12:41。どれも JST）続けて行った。

## 測り方

計測の道具は [scripts/nfr05-footprint.py](../../scripts/nfr05-footprint.py) である。
Python 3 の標準ライブラリだけを使い、Linux でだけ動く。
エディタを 80 列 24 行の偽の端末（pty）の中で起動し、次の手順で 1 回を測る。

1. 偽の端末を制御端末にしてエディタを起動する。`XDG_CONFIG_HOME`、`XDG_DATA_HOME`、`XDG_STATE_HOME`、`XDG_CACHE_HOME` は 1 回ごとに作る空のディレクトリにし、利用者の設定と拡張機能を読ませない。`TERM` は `xterm-256color` にする
2. 端末への出力を読み続け、出力が 0.5 秒途切れたら、最初の画面を描き終えたとみなす
3. 必要なら（拡張機能を使う条件では 3 秒）待ってから、`/proc/<pid>/status` の `VmRSS` を、エディタのプロセスと、その子孫のプロセスのそれぞれで読む
4. `<Esc>:q!<CR>` を送って終わらせる

起動から最初の画面までの時間は、起動（fork の直前）から、途切れるまでの出力のうち文字を含む最後の read までの時間とする。
文字を含むかは、エスケープシーケンスを除いて空白でない文字が残るかで決める。
文字を含む read に限るのは、Neovim が画面の内容を描いた約 85 ms 後に、カーソルの表示とフォーカスの通知の有効化（`ESC[?1004h ESC[?25h`）だけを出力するためである。
この出力を含めると、Neovim の値は画面の内容と関係なく約 103 ms になる。

Neovim は起動のときに端末へ問い合わせ（装置属性、背景の色など）を送り、応答を待つ。
応答が無いと、約 100 ms 待ってから最初の画面を描いた（`E1568: Terminal did not respond to DSR request` を表示する）。
実際の端末は応答を返すので、道具は Neovim が待つ問い合わせにだけ xterm と同じ形の応答を返す（`ANSWERS`）。
vi-imitation と Vim は、応答を待たずに最初の画面を描いた。

拡張機能を使う条件では、tree-sitter の拡張機能が構文の色を付けた画面を、最初の画面の約 100 ms 後に描く。
このため、文字を含む最初の read の時刻（`first_text_ms`）と、色を付けた画面の時刻（`text_ms`）を分けて書く。

比べるエディタの起動のしかたは次のとおりである。

| 名前 | コマンド | 読む設定 |
|---|---|---|
| vi-imitation | `bin/vi-imitation <ファイル>`（拡張機能の無いディレクトリに置いた実行ファイル） | 無し |
| vi-imitation（拡張機能あり） | 実行ファイルの隣の `extensions/` に `make dist` と同じ形で tree-sitter と LSP の拡張機能を置く | LSP の拡張機能の Go の言語サーバーを偽の言語サーバーにする設定ファイル |
| Vim（`--clean`） | `vim --clean -n -i NONE <ファイル>` | Vim の既定の設定（`defaults.vim`。構文の色とファイルの種類の判定が有効） |
| Vim（`-u NONE`） | `vim -Nu NONE -n -i NONE <ファイル>` | 無し |
| Neovim（`--clean`） | `nvim --clean -n -i NONE <ファイル>` | Neovim の既定の設定 |

Neovim は、端末の画面を描くプロセスと、編集を担うプロセス（`nvim --embed`）の 2 つで動く。
Neovim の RSS は 2 つの合計で書く。

偽の言語サーバーは、LSP の拡張機能のテストが使う `cmd/vi-imitation-ext-lsp/testdata/fakels` を `go build` したものである。
gopls を使わないのは、本体の RSS を測る条件を、言語サーバーの実装と、開いたファイルの外のパッケージの量に依存させないためである。
設定ファイルは次の内容で、`command` に偽の言語サーバーの絶対パスを書く。

```jsonc
{
  "extensions": {
    "settings": {
      "lsp": { "servers": { "go": { "command": "/path/to/fakels" } } }
    }
  }
}
```

開いたファイルは次のとおりである。

| ファイル | 行数 | バイト数 | 内容 |
|---|---|---|---|
| 空のファイル | 0 | 0 | |
| 10,000 行のテキスト | 10,000 | 680,000 | `line 000001: the quick brown fox jumps over the lazy dog 0123456789` の形の行 |
| 100,000 行のテキスト | 100,000 | 6,800,000 | 同じ形の行 |
| 10,000 行の Go のソース | 10,002 | 162,466 | 10 行の関数（コメント、`if`、文字列のリテラルを含む）を繰り返したもの |

1 つの条件の実行は、たとえば次のとおりである。
`ext/` は、本体と `extensions/treesitter/`、`extensions/lsp/` を並べたディレクトリである。

```console
$ scripts/nfr05-footprint.py --runs 20 --label me -- bin/vi-imitation lines10000.txt
$ scripts/nfr05-footprint.py --runs 20 --label me-ext --wait 3 --config config.jsonc -- ext/vi-imitation lines10000.go
```

## 起動から最初の画面までの時間

値は、20 回の中央値を 3 組分（1 組目 / 2 組目 / 3 組目）と、60 回の最小と最大である。
単位は ms である。

| エディタ | 空のファイル | 10,000 行 | 100,000 行 |
|---|---|---|---|
| vi-imitation | 4.3 / 4.3 / 4.2（3.1〜4.6） | 7.5 / 7.5 / 7.5（5.4〜8.2） | 26.9 / 27.0 / 27.4（20.2〜30.3） |
| Vim（`--clean`） | 14.4 / 14.4 / 14.5（10.7〜16.2） | 16.0 / 16.1 / 15.9（11.5〜17.5） | 29.2 / 29.3 / 29.5（20.9〜31.6） |
| Vim（`-u NONE`） | 5.8 / 5.8 / 5.8（4.3〜7.4） | 7.5 / 7.4 / 7.5（5.6〜7.9） | 20.6 / 20.8 / 20.6（15.2〜22.6） |
| Neovim（`--clean`） | 16.8 / 16.5 / 16.6（12.4〜17.5） | 17.3 / 17.5 / 17.4（12.5〜18.6） | 25.2 / 25.1 / 25.1（17.8〜27.5） |

10,000 行の Go のソースを開いた値は次のとおりである。

| 条件 | 文字を含む最初の read | 色を付けた画面 |
|---|---|---|
| 拡張機能なし | 5.4 / 5.3 / 5.3（4.1〜8.9） | （色を付けない） |
| tree-sitter と LSP の拡張機能あり | 5.7 / 5.7 / 5.7（4.4〜6.2） | 107.2 / 106.9 / 107.0（75.9〜114.2） |

3 組の中央値の差は、どの条件でも 0.5 ms 以内だった。
60 回の最小と最大の幅は、多くの条件で中央値の 3〜4 割だった。
拡張機能なしで Go のソースを開いた条件だけは、最大が 8.9 ms で、幅が中央値の約 9 割だった。
他のプロセスの影響は、この幅の中に入っていると考えている（区別はしていない）。

vi-imitation の最初の出力（代替画面への切り替え）は、起動から約 3.7 ms で出た。
10,000 行のファイルでは、そこから画面の内容が出るまでに約 4 ms かかった。
100,000 行では最初の画面まで約 27 ms で、行数に比例して伸びる部分があると見ている（ファイルの読み込みと行への分割と推測しているが、内訳は測っていない）。

拡張機能は非同期に読み込まれる（NFR-04）ので、拡張機能があっても最初の画面までの時間は 0.3 ms ほどしか変わらなかった。
色を付けた画面の約 107 ms には、拡張機能のプロセスの起動、初期化の往復、10,000 行の構文の解析が含まれる。

## メモリの使用量

値は `VmRSS` で、20 回の中央値を 3 組分と、60 回の最小と最大である。
単位は KiB である。
`VmHWM`（RSS の最大）は、どの回も読んだ時点の `VmRSS` と同じだった。

| エディタ | 空のファイル | 10,000 行 | 100,000 行 |
|---|---|---|---|
| vi-imitation | 6,100 / 6,058 / 6,070（5,832〜6,252） | 10,342 / 10,306 / 10,444（9,864〜11,300） | 36,264 / 36,452 / 36,302（34,984〜45,080） |
| Vim（`--clean`） | 13,070 / 13,052 / 13,094（12,968〜13,164） | 13,824 / 13,784 / 13,812（13,672〜13,908） | 20,590 / 20,600 / 20,570（20,484〜20,664） |
| Vim（`-u NONE`） | 9,762 / 9,744 / 9,722（9,624〜9,848） | 10,586 / 10,560 / 10,592（10,496〜10,716） | 17,428 / 17,446 / 17,428（17,324〜17,580） |
| Neovim（`--clean`、2 プロセスの合計） | 22,426 / 22,316 / 22,396（22,076〜22,712） | 23,102 / 23,124 / 23,212（22,724〜23,376） | 30,042 / 30,030 / 30,056（29,748〜30,320） |

vi-imitation の 100,000 行の RSS は、60 回のうち 6 回が 38 MiB（38,912 KiB）を超え、最大は 45,080 KiB だった。
他の条件より揺れが大きいのは、Go のガベージコレクションが RSS を読んだ時点までに走ったかどうかで変わるためと推測している（確かめていない）。

100,000 行のファイルを開いたときの増加は、空のファイルとの差で、vi-imitation が約 30 MiB、Vim（`--clean`）が約 7.3 MiB だった。
ファイルは 6.8 MB なので、vi-imitation はファイルの大きさの約 4.5 倍を使っている。
バッファの行の持ち方（`internal/buffer`）が原因と推測しているが、内訳は測っていない。

10,000 行の Go のソースを開き、最初の画面から 3 秒待った後の値は次のとおりである。

| プロセス | 拡張機能なし | 拡張機能あり |
|---|---|---|
| 本体（`vi-imitation`） | 7,234 / 7,234 / 7,286（7,076〜7,400） | 15,040 / 15,072 / 15,084（13,344〜16,596） |
| `vi-imitation-ext-treesitter`（glibc を静的にリンク） | | 22,392 / 22,218 / 22,460（18,664〜24,000） |
| `vi-imitation-ext-lsp` | | 8,756 / 8,764 / 8,736（8,420〜9,008） |
| 偽の言語サーバー | | 5,016 / 5,006 / 5,004（4,876〜5,064） |
| 合計 | 7,234 / 7,234 / 7,286 | 51,348 / 50,926 / 50,960（46,696〜53,108） |

拡張機能を起動すると、本体の RSS は約 7.7 MiB 増えた。
増えた分は、拡張機能との接続と、tree-sitter が送る色の一覧を本体が持つ分と推測しているが、内訳は測っていない。

|---|---|---|---|
| `vi-imitation`（本体） | 7,447,701 | 7.10 | 4,960,416 |
| `vi-imitation-mcp-bridge` | 3,091,548 | 2.95 | |
| `vi-imitation-ext-line` | 4,563,845 | 4.35 | |
| `vi-imitation-ext-acp` | 5,015,546 | 4.78 | |
| `vi-imitation-ext-mcp` | 4,920,803 | 4.69 | |
| `vi-imitation-ext-lsp` | 5,081,894 | 4.85 | 3,371,168 |
| `vi-imitation-ext-dap` | 5,195,566 | 4.95 | |
| `vi-imitation-ext-treesitter`（glibc を静的にリンク） | 7,061,480 | 6.73 | |
| `vi-imitation-ext-script` | 29,603,513 | 28.23 | 20,652,192 |

本体は、#66 で測ったとき（コミット `b4797f5`、`--version` だけが動いた時点）の 2,468,266 バイトから、端末の制御（`internal/term`）、編集のイベントループ（`internal/editor`）、設定ファイルの読み込み（`internal/config`）などが入って約 3 倍になった。
tree-sitter の拡張機能は、#66 の時点で glibc を静的にリンクしたものが 6,668,576 バイト、musl を静的にリンクしたものが 5,693,656 バイトだった。
この計測では musl-gcc が無いので、配布物の形のサイズは測っていない。
配布物の `tar.gz`（`make dist`）は、musl の著作権の文面（`MUSL_COPYRIGHT`）が手元に無いので作っていない。

比較の目安として、Vim と Neovim のファイルの大きさを書く。
どちらも共有ライブラリと実行時のファイル（runtime）を別に要するので、vi-imitation の静的にリンクした 1 つの実行ファイルとは数え方が違う。

| Vim がリンクする共有ライブラリ（`ldd` が示す 11 個の合計。動的リンカーを除く） | 13,871,520 |
| Vim の runtime（`/usr/share/vim/vim91`） | 37,699,214 |
| Neovim の実行ファイル（`bin/nvim`） | 11,002,760 |
| Neovim の runtime（`share/nvim/runtime`） | 22,284,317 |
| Neovim の `lib/nvim`（同梱の構文の解析器） | 2,727,232 |

## 目標値の案

2026-11-16 に、オーナーが 3 つの項目のすべてで B（推奨）を採った（#122）。
100,000 行の条件と、拡張機能を起動した後の本体の条件は、要件定義に入れていない。
以下は、採った案と比べた案を、決める前の形のまま残す。

案は、上の実測（コミット `8a367ac`、2026-11-16）と、同じマシンの Vim と Neovim の値から出す。
どの案も、要件定義の NFR-05 にそのまま書ける形（条件と上限）にした。
推奨の理由のうち、CI のマシンでの揺れの大きさは測っていないので推測である。

### 起動から最初の画面までの時間

条件は「拡張機能なしで 10,000 行のテキストファイルを開き、文字を含む最初の画面を描き終えるまで」とする。

| 案 | 上限 | 現状（p50 7.5 ms、最大 8.2 ms）との関係 | 長所 | 短所 |
|---|---|---|---|---|
| A | 50 ms | 約 6.7 倍の余裕 | CI の共用のマシンで揺れても落ちにくい | 現状の 6 倍遅くなっても満たすので、退行を捕まえにくい |
| B（推奨） | 20 ms | 約 2.7 倍の余裕。Vim（`--clean`）と Neovim の p50（16〜17 ms）を少し上回る | 「Vim や Neovim と同じくらいに速い」を数で表せる | CI で測るなら、揺れの大きさを確かめてから上限の使い方を決める必要がある |
| C | 10 ms | 約 1.3 倍の余裕 | 現状からの退行を細かく捕まえる | 他のプロセスの影響で手元でも超えうる（最大 8.2 ms）。機能を足す余地が小さい |

100,000 行でも条件を置くなら、B と同じ考え方で 60 ms（現状 p50 27 ms の約 2.2 倍、Vim の 29 ms の約 2 倍）を案とする。

### メモリの使用量

条件は「拡張機能なしで 10,000 行のテキストファイルを開き、最初の画面を描いた後の本体の `VmRSS`」とする。
拡張機能のプロセスのメモリは、設定の `extensions.memoryLimitMb`（FR-20）で上限を付けられるので、NFR-05 の対象を本体に限る案にした。

| 案 | 上限 | 現状（p50 約 10.1 MiB、最大 11.0 MiB）との関係 | 長所 | 短所 |
|---|---|---|---|---|
| A | 32 MiB | 約 3 倍 | 機能を足しても当面は満たす | Neovim（22.6 MiB）より大きくても満たす |
| B（推奨） | 16 MiB | 約 1.6 倍。Vim（`--clean`）の 13.5 MiB を少し上回る | 「Vim と同じくらいに軽い」を数で表せる。RSS の揺れ（60 回で 1.4 MiB）に余裕がある | 機能を足すときに、メモリを意識する必要がある |
| C | 12 MiB | 約 1.2 倍 | 退行を細かく捕まえる | Go のランタイムとガベージコレクションの揺れで超えうる |

100,000 行の条件も置くなら、B と同じ考え方で 64 MiB（現状の最大 45,080 KiB の約 1.5 倍）を案とする。
ただし 100,000 行では vi-imitation が Vim と Neovim より大きく、上限を Vim 並み（32 MiB 程度）にするなら、バッファの行の持ち方の改善が先に要る。
拡張機能を起動した後の本体にも条件を置くなら、B と同じ考え方で 24 MiB（現状の最大 16,596 KiB の約 1.5 倍）を案とする。

### 実行ファイルのサイズ

条件は「`make build` が作る本体の実行ファイル」とする。
拡張機能は利用者が選んで置くもので、`vi-imitation-ext-script` だけが 28 MiB と大きいので、本体に限る案にした。

| 案 | 上限 | 現状（7.10 MiB）との関係 | 長所 | 短所 |
|---|---|---|---|---|
| A | 16 MiB | 約 2.3 倍 | 機能を足しても当面は満たす | Neovim の実行ファイル（10.5 MiB）より大きくても満たす |
| B（推奨） | 10 MiB | 約 1.4 倍。Neovim の実行ファイルより小さい | `make build` を変えずに、機能を足す余地がある | 依存を足すときにサイズを意識する必要がある |
| C | 6 MiB | 現状を超えている。`-ldflags '-s -w'` で削る（4.73 MiB）と満たす | Vim の実行ファイル（3.94 MiB）に近い | `make build` を変える必要がある。削るとデバッグ情報（DWARF）が無くなり、デバッガーで変数を読めなくなる |

## CI での検査

目標値が決まった後に、CI の検査を次の形で入れた（#122）。
どの検査も、上限は要件定義の値そのものを使う。

| 項目 | 検査 | 判定 |
|---|---|---|
| 実行ファイルのサイズ | `make build-check` が実行する `internal/distcheck` の `TestBuildMainSize` | 判定しない。`bin/vi-imitation` の大きさをログに出すだけである。上限は 10 MiB で始め、2026-11-21 に 12 MiB に上げ、2026-11-26 のオーナーの決めで要件から外して努力目標にした（要件定義の NFR-05 の注。#442） |
| 起動から最初の画面までの時間と本体の RSS | `make footprint-check` が単独で実行する `cmd/vi-imitation` の `TestFootprintInPTY` | 最初の 3 回を捨て、続く 20 回の中央値が 20 ms 以下、16 MiB（16,384 KiB）以下 |

`TestFootprintInPTY` は、この文書の道具と同じ手順で 1 回を測る。
80 列 24 行の偽の端末、`TERM=xterm-256color`、空の `XDG_CONFIG_HOME` などの 4 つのディレクトリ、同じ形の 10,000 行のファイル、出力が 0.5 秒途切れるまでの文字を含む最後の read、その後の `VmRSS`、`<Esc>:q!<CR>` での終了である。
起動の時刻は、道具は fork の直前、テストは `exec.Cmd.Start` の直前で取る。
テストは、テストの実行ファイル（`-race` と `-cover` の計測を含む）ではなく、`make build` の本体を、環境変数 `VI_IMITATION_BUILD_DIR` で受け取って起動する。
指定が無ければ飛ばすので、`make check` では実行されない。
他のテストと CPU を取り合わないよう、`make footprint-check` はこのテストだけを `-run` で選んで実行する。

最初の 3 回を捨てるのは、1 回目の起動が実行ファイルとテキストファイルをページキャッシュへ読み込む分だけ遅れうるためである（この遅れは測っていない）。

検査を入れた PR #123 の CI（GitHub Actions の `ubuntu-latest`、2026-11-16 の run 43801106149 と 43801554489）での値は次のとおりで、どれも上限に余裕があった。
時間と RSS は 20 回の中央値（最小〜最大）を、run ごとに書く。

| 項目 | run 43801106149 | run 43801554489 | 上限 |
|---|---|---|---|
| 起動から最初の画面まで | 6.0 ms（5.6〜9.1） | 5.9 ms（5.4〜6.6） | 20 ms |
| 本体の `VmRSS` | 9,276 KiB（9,164〜10,076） | 9,354 KiB（9,156〜10,008） | 16,384 KiB |
| 本体の実行ファイル | （ログに出していない） | 7,447,701 バイト | 10,485,760 バイト |
