# Vim との違い

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-11-16 |
| 位置づけ | Vim 9.1 との食い違いのうち、見つけたが直さないと決めたものの一覧 |
| 比べた Vim | Vim 9.1 を Ex モードでない起動（`vim -Nu NONE -i NONE -n --not-a-term`）で動かし、`feedkeys(keys, "xt")` で入力した結果 |

要件定義 1 章は、Vim との 100% の互換を目指さないとしている。
このため、Vim との細かい食い違いは、日常の編集で困るもの（バッファの内容が変わるもの、よく打つ操作で起きるもの）だけを直し、残りをここに書く（#89）。

個々の関数の振る舞いの違い（要件が Vim と違う挙動を定めているもの。FR-09 の正規表現の文法など）は、その関数の doc コメントに書く（`internal/command` のパッケージの doc コメント）。
この一覧には、doc コメントの 1 か所に収まらない違いと、#89 とそのレビュー（PR #100）で見つけた未実装の機能を書く。
未実装の機能を全て並べたものではない（実装する操作の一覧は #9 の案にある）。

要件定義が引き継がないと定めた Vim の仕様（要件定義 1.1）は、この一覧に入れない。
レジスターの名前と履歴（FR-50〜FR-53）はその 1 つで、`"0`〜`"9`、`"-`、`""`、`".`、`":`、`"/` などは無く、指定すると `E354` で失敗する。
ビジュアルモードの bracketed paste で置き換えたテキストも、Vim と違ってレジスターにも履歴にも入れない（FR-51）。
使い方は [usage.md](usage.md) の「レジスターと履歴」にある。

## 編集の禁止と Vim の 'modifiable'、'readonly' の違い

編集の禁止（FR-85）は、Vim の `'modifiable'` を切った状態に合わせ、断るときのエラー番号も同じ `E21` にした（基本設計 4.6）。
2026-11-18 に Vim 9.1 を `vim -Nu NONE -n --not-a-term` で起動し、`setline()` で 3 行を置いてから `:set nomodifiable` とし、
ノーマルモードのキーは `:silent! exe "normal " . keys . "\<Esc>"`、Ex コマンドは `:silent! exe cmd` で入れて、`v:errmsg`、`"` のレジスター、バッファの内容を比べた。
キー 47 件、Ex コマンド 17 件を試した。
ほかに、`-R` と `-M` で起動したときのオプション、`'modifiable'` を切ったバッファの `:e!` と、`BufWritePre` の中の `setline()` を確かめた。

次のものは Vim と同じである（`internal/command` の `TestReadOnlyRefusesChanges` と `TestReadOnlyExCommands` で確かめる）。

- `x`、`X`、`d`、`c`、`D`、`C`、`S`、`r`、`~`、`g~`、`gU`、`gu`、`J`、`p`、`P`、`>>`、`<<`、`u`、`<C-r>`、ノーマルモードの `U`、`.`、インサートモードへ移る `i`、`a`、`I`、`A`、`o`、`O`、ビジュアルモードの `d`、`>`、`U`、`~` は `E21` で断り、バッファもレジスターも変わらない。`i` はインサートモードへ移らずに断る
- `y`、`yy`、`Y`、ビジュアルモードの `y`、移動、検索、`qaq` は使える
- `@a` は断らず、再生の中の `x` などが `E21` で断られた時点で止まる
- `:d`、`:s`、`:r`、`:{範囲}!` は、範囲と引数を確かめる前に `E21` で断る（`:5d` も `:2,1d` も `:s/一致しない/x/` も `E21`）。`:g/foo/d` は cmd の中の `:d` が `E21` になる
- 外での変更の読み直し（`:e!`）は断らない
- ノーマルモードの端末からの貼り付け（bracketed paste）は `E21` で断って貼ったテキストを捨て、`.` の記録を変えない（PR #199 のレビューが tmux 3.4 の `paste-buffer -p` で確かめた。`TestReadOnlyPaste`）

違うものは次のとおりである。

| 違い | 例 | Vim 9.1 | この実装 | 理由 |
|---|---|---|---|---|
| `-R` の意味 | `-R a.txt` で起動して `x`、`:w` | `'readonly'` を立てるだけで、`x` は W10 の警告を出して編集できる。`:w` は `E45` で断り、`:w!` で書く | 編集を禁止して開き、`x` は `E21` で断る。`:w` は断らない | FR-119。Vim の `-R` は誤って上書きしないためのもので、このエディタの `-R` は誤って編集しないためのものである。Vim で近いのは `-M`（`'modifiable'` と `'write'` を切る）だが、`:w` を断らない点が違う |
| 保存を断らない | `:set nomodifiable` の後に `:w` | 書き出す（`'modifiable'` は保存を断らない） | 同じく書き出す | #177 の裁定。禁止するのは編集で、保存ではない。Vim の `'readonly'` の `E45` には当たるものが無い |
| 切り替えのコマンド | — | `:set nomodifiable`、`:set modifiable` | `:readonly`（`:reado` まで省略できる）で切り替え、「編集を禁止しました」か「編集の禁止を解きました」を出す | FR-86。`:set` はあるが（[`:set` と Vim の `:set` の違い](#set-と-vim-の-set-の違い)）、編集の禁止は設定の表の項目にしていない（`:set nomodifiable` は `E518`）。コマンドの名前は仮 |
| ノーマルモードの `>` と `<` | `>` | オペレーターとして次のキーを待ち、`<Esc>` で取り消すので `E21` にならない | `>>` と同じくすぐずらすので、`E21` で断る | FR-76 で `>` と `<` を次のキーを待たない操作にした |
| 拡張機能の編集 | 拡張機能の `buffer/edit` | Vim script の `setline()` は `E21` で断る | `buffer/edit` を `E21` の文言の誤りの応答で断る。編集の無い（`noLines` と `endOfLine` だけの）要求も断る。`command/execute` が返したトランザクションも適用せずに `E21` を出す | FR-118 |
| 保存の前の拡張機能の編集 | 禁止中に `:w` し、整形の拡張機能が `buffer/willSave` で編集を返す | `BufWritePre` の中の変更は `E21` で断る | `buffer/willSave` を送らず、警告も出さずに今の内容を書き出す | 保存を断らないため。適用できない整形を問い合わせない |

## `:set` と Vim の `:set` の違い

このエディタの設定は、点で区切った正規の名前（`lineNumber.show` のような名前）の項目を 1 つの表で持ち、正規の Ex コマンド `:option.set` と `:option.get` で読み書きし、真偽の項目は `:option.toggle` で反転する（FR-131、FR-132、FR-155。基本設計 7.3）。
`:set`（`:se`）は、Vim の書き方の一部をこの 3 つの呼び出しに変換する別名である（FR-133）。`:set 名前!` は `:option.toggle` の呼び出しに変換する（#299）。
Vim との完全な互換は目指さない（#264 のオーナーの方針）。
使い方と項目の一覧は [usage.md](usage.md) の「実行中に設定を変える」にある。
Vim の名前から正規の名前への対応は `:set` の別名が持ち、2026-11-20 の時点で受け付ける Vim の名前は `filetype`、`number`、`numberwidth` の 3 つである（`number` と `numberwidth` は #268 で足した）。

2026-11-20 に Vim 9.1 を `vim -Nu NONE -n --not-a-term` で起動し、`execute()` で `:set` の 44 通りの書き方を流して、出力とエラーを比べた。
エラー番号（`E518`、`E474`、`E521`、`E488`、`E481`）は、次の表に書いたもののほかは Vim と同じである。
次のものは違う。

| 違い | 例 | Vim 9.1 | この実装 | 理由 |
|---|---|---|---|---|
| 短い名前 | `:set ft=go` | `'filetype'` を変える | `E518`（知らない設定） | 正規の名前は何の設定かが名前で分かるものにし、`:set` が受け付けるのも省略しない Vim の名前だけにした |
| `inv` の接頭辞、`+=`、`-=`、`^=`、`&` | `:set invnumber`、`:set ts+=4`、`:set ft&` | 反転する、足す、引く、掛ける、既定値に戻す | `E518` | 受け付ける書き方を 6 つに絞った。反転は `名前!` で書ける |
| 引数の無い `:set` | `:set` | 既定値から変えた項目を一覧にする | `E471`（引数が要る） | 同上 |
| `:set!` と範囲 | `:set! ts?`、`:3set ts?` | `:set!` は値を出す。範囲は `E481` | `:set!` は `E477`、範囲は `E481` | `!` を取らない別名にした |
| `:setlocal`、`:setglobal` | `:setlocal ft=go` | バッファか窓の値だけを変える | `E492`（コマンドではない） | 範囲は項目ごとに 1 つに決まっているので、`:set` で足りる |
| 値を読んだときの出力 | `:set ft?`、`:set number?` | `  filetype=go`、`  number` か `nonumber` | `filetype=go`、`lineNumber.show=true` のように、正規の名前と値を `=` でつないで出す | `:option.get` の呼び出しに変換するため |
| 値の末尾の空白 | `:set cms=%s\ ` | `\ ` を空白として読み、値は `%s ` になる | 値は `%s` になる。値の中の `\ ` は Vim と同じく空白として読む（#327 で足した） | `:option.set` の呼び出しに変換し、`:option.set` は値の末尾の空白を除くため |
| `名前?x`、`名前!x` | `:set filetype?x` | `E488`（余計な文字） | `E518` | `?` と `!` を引数の末尾でだけ読むため |
| 名前と `=` の間の空白 | `:set ts =4` | `:set ts=4` と同じ | `ts` と `=4` の 2 つの引数として読み、`=4` は `E518` | 空白で引数を区切るため |
| 整数の 16 進と 8 進 | `:set ts=0x10` | 16 として読む | `E521`（整数の値は 10 進だけ） | #264 で、整数は 10 進と決めた |

整数の項目ごとの範囲は、#268 で設定の表の欄（`option.Def.Range`）にした。
範囲の下限より小さい値は `E487`、上限より大きい値は `E474` にする。
2026-11-20 に Vim 9.1 で、`:set numberwidth=0` と `:set numberwidth=-1` が `E487`、`:set numberwidth=21` が `E474` になることを確かめ、`numberwidth` は Vim と同じ番号になる。
番号は項目の名前で分けない。
同じ日に、Vim 9.1 が下限が 0 の項目の負の値（`:set textwidth=-1`、`:set scrolloff=-1`）も `E487` にすることを確かめたので、下限の側の番号は下限が 0 の項目にも合う。
上限の側の番号を確かめたのは `numberwidth` だけなので、上限のある項目を足すときは、その項目でも `E474` になるかを確かめる。
整数に収まらない値（`:set numberwidth=99999999999999999999`）は、正なら `E474`、負なら `E487` にし、Vim 9.1 と同じ番号になる（PR #272 のレビューの推奨 2）。

## vim-sandwich との違い

囲みの操作（`sa`、`sd`、`sr`。FR-73〜FR-75）は、vim-sandwich の既定の動作を写す。
期待値は、2026-11-18 に Neovim 0.12.5 を `nvim --clean --headless` で起動し、runtimepath に vim-sandwich だけを足して取った（`internal/command/surround_test.go` の `sandwichCases`）。
次の点は vim-sandwich と違う。

| 違い | vim-sandwich | この実装 | 理由 |
|---|---|---|---|
| `sa` の前の回数 | 囲む回数（`2saiw(` は `((foo))`） | 対象の回数に掛ける（`2saiw(` は `sa2iw(`） | 回数は既存のオペレーターと揃える（#183 の契約） |
| `t`、`T`、`f`、`F`、`i`、`I` | タグ、関数の呼び出し、入力した文字列の囲み | ただの文字として前と後ろを囲む | 基本設計 4.8 が、組の括弧以外の文字を同じ文字の囲みとしている |
| `<CR>` | 行単位の囲み（`sa` は空の行を足し、`sr` は改行に替える） | 囲みの文字に使えず、何も変えずに失敗する | 使う場面が少ない |
| ビジュアルモードの `sa`、`sd`、`sr` | 選択を囲む、選択の両端の囲みを消す、替える | 無い。ビジュアルモードの `s` は選択を消して入力する | 基本設計 4.8 と要件定義 1.1 |

## 構文のまとまりの an と in と Neovim の違い

tree-sitter の拡張機能の `an` と `in`（FR-240。#373）は、キーを Neovim 0.12.5 の既定の `an` と `in`（`:help v_an`、`:help v_in`。`$VIMRUNTIME/lua/vim/treesitter/_select.lua`）と同じにしたが、選ぶ単位が違う。
期待値は、2026-11-22 に Neovim 0.12.5 を `nvim --clean --headless` で起動し、runtimepath に tree-sitter-go v0.25.0 の `src/parser.c` から作った `parser/go.so` を足し、`vim.treesitter.start()` の後に `feedkeys(keys, "xt")` で入力して取った。
例は、次の Go の関数の `a += i` の `a` の上にカーソルを置いたものである。

```go
func add(a int, b int) int {
	f := func(x int) int { return x + 1 }
	if a > 0 {
		for i := 0; i < b; i++ {
			a += i
		}
	} else {
		b = 2
	}
	return f(a) + b
}
```

| 違い | 例 | Neovim 0.12.5 | この実装 | 理由 |
|---|---|---|---|---|
| `an` の単位 | `vany` | どの種類の節も 1 段ずつ選ぶ。`a` の識別子の次は `a += i`（文） | 中に文や要素を持つまとまりだけを選ぶ。`for` の文の全体（3 行） | オーナーの決め（#373）。種類によらず、まとまりの単位で選ぶ |
| 同上 | `vanany`、`v3any` | `a += i` と改行、`{` から `}` までの `for` の本体 | `if` と `else` の全体、関数の全体 | 同上 |
| `in` の意味 | `viny` | 子の節（`a`） | まとまりの中身（`for` の本体の `a += i` の行） | Vim の `i` の慣習（`iB` は括弧の中身）に合わせた（#373） |

オペレーターの後の `an` と `in`（`dan`、`cin`）、回数、ドットリピート（`dan.` は 1 段外側を消す）、マクロ（`qqvanyq@q`）は、Neovim 0.12.5 でも使え、この実装でも使える。
Neovim 0.12.5 の既定の割り当て（`$VIMRUNTIME/lua/vim/_core/defaults.lua`）は、`an` と `in` をビジュアルモードとオペレーターの後の両方（`{ 'x', 'o' }`）に割り当てている。
#373 の issue の背景は「Neovim 0.12.5 の `an` と `in` はビジュアルモードだけである」としていたが、2026-11-22 に確かめたところ、`dan` で `a += i` が消えた。

## 正規表現の書き方の対応

検索（`/`、`?`）と Ex コマンド（`:s`、`:g`）の正規表現は、FR-09 のとおり Go の `regexp`（RE2）の文法で書く。
Vim の書き方は、Go では別の意味になるか誤りになる。
Vim の書き方の `\<`、`\>`、`\|`、`\(`、`\)`、`\{`、`\+`、`\=`、`\v` を含むパターンが見つからなかったときは、E486 に Go の文法で書く旨を添える（`internal/command/search.go` の `vimStyleHint`）。

| 意味 | Vim の書き方（既定の `magic`） | Go の regexp（RE2）の書き方 | Vim の書き方を Go で打ったときの意味 |
|---|---|---|---|
| 単語の始まりと終わり | `\<foo\>` | `\bfoo\b`（ASCII の英数字と `_` の境界だけ） | `<foo>` の文字どおり |
| どちらか | `a\\|b` | `a\|b` | `a\|b` の文字どおり（縦棒の文字に一致する） |
| グループ | `\(ab\)` | `(ab)` | `(ab)` の文字どおり |
| 括弧の文字 | `(` | `\(` | `(` はグループの始まりで、閉じなければ E383 |
| 1 回以上 | `a\+` | `a+` | `a+` の文字どおり |
| 0 回か 1 回 | `a\=`（`a\?`） | `a?` | `\=` は `=` の文字どおり。`\?` は `?` の文字どおり |
| 回数の範囲 | `a\{2,3}` | `a{2,3}` | `a{2,3}` の文字どおり |
| very magic | `\v(a\|b)+` | 書き方を切り替えずに `(a\|b)+` | `\v` は垂直タブ（U+000B） || 大文字と小文字を区別しない | `\cfoo` | `(?i)foo` | `\c` は誤りで E383 |
| 任意の文字の 0 回以上（最短） | `.\{-}` | `.*?` | `.{-}` の文字どおり |

表のソースでは、縦棒を表の区切りと分けるために `\|` と書いている。描かれた表の縦棒は 1 文字の `|` であり、Vim の書き方の列の「どちらか」だけが `\` と `|` の 2 文字である。

## 直したもの

#89 で直したものを、比べるときのために残す。

- ビジュアルモードのカーソルは、j、k、`$` で移った短い行や、`l` で最後の文字から進んだ行では、Vim と同じく行末の後（NUL の位置）に置く。文字単位の選択の始まりがここにあれば、その行の改行から選び（`a` と `bcd|e` の `vkd` は `a` を残す）、終わりがここにあれば、その行の改行まで選ぶ（`ab|c` と `d` と `e` の `vjd` は `abe` になる）。ここから `h` で戻る列も Vim と同じになる（`ab` と `cdef|g` の `vkhCX<Esc>u` のカーソルは 1:1）。表は `internal/command/visual_eol_test.go` にある
- 選択の終わりが行末の後のとき、`>` と `<` は終わりの行まで字下げし、次の行は字下げしない（`ab|c`、`d`、`e` の `vj>` は `e` を残す）
- 複数の行の選択のドットリピートは、終わりの列が繰り返す先の行の長さ以上のときだけ、その行の改行まで消す（Vim の `resel_VIsual_vcol`。`$` の後だけは常に改行まで消す）
- ビジュアルモードの間に拡張機能の編集が届いても、行末の後のカーソルを最後の文字へ丸めない（`State.SetCursor`）。拡張機能へ返す `editor/state` の選択は、終わりが行末の後ならその行の改行まで含め、`d` が消す範囲と揃える
